# Audit — decision & reporting scripts

Scope: `stocklab/journal.py`, `scripts/journal.py`, `scripts/open_questions.py`,
`scripts/price_vs_position.py`, `scripts/find_targets.py`,
`scripts/weekly_briefing.py`, `docs/WEEKLY_PLAYBOOK.md`.

Every script in scope was run against the real repo data. `journal/decisions.csv`
was **not** written to — all journal behaviour was reproduced on temporary copies
under `/tmp/.../scratchpad/` and in a sandbox tree
(`scripts/` + `briefings/` copied, `stocklab/` and `data_cache/` symlinked).

**Environment at audit time (2026-08-13 12:30–13:10 UTC).** `scripts/update_prices.py`
was running concurrently, so the live store was mid-refresh: panel 2018-01-02 →
**2026-08-12**, 2,992 tickers, last-date split **135 on 08-12 / 2,648 on 08-11 /
205 on 08-10**, i.e. **4.5 % aligned**. That is not a contrived state — it is the
exact partial-refresh condition `weekly_briefing.MIN_ALIGNED_SHARE` was added to
detect, and several findings below are about which scripts notice it. Other audit
agents were writing to the repo at the same time; untracked artifacts that appear
and vanish in the repros below (`analysis_pack_2026-08-12.json`,
`price_vs_position_2026-08-12.md`) are regenerated by the commands shown.

Verdict summary: **2 CRITICAL, 7 HIGH, 11 MEDIUM, 7 LOW.** The two most damaging
are both silent-corruption-of-the-decision-output: a regex that reads positioning
scores out of the wrong table, and an `open_questions` section that reports "that
is a complete answer" when its input file is simply absent.

## 1. `price_vs_position.py` reads positioning scores out of ANY table in the ranking file — FCX 84 % becomes 27 %

**Severity: CRITICAL**

**What breaks.** `load_positioning()` (line ~78) applies its regex to *every line
of the file*, not to the ranking table, and stores the **first** match per ticker
(`rows.setdefault`). `briefings/rank_thesis4_metals_2026-08-12.md` opens with a
short-interest table at line 16 whose cells are `| **FCX** | 27.1–27.9M shares, …`.
The regex `\*\*(TICKER)\*\*\s*\|\s*\*{0,2}\s*(\d{1,3})\s*%?` matches `27` there,
and because it appears 45 lines *before* the real ranking table, `setdefault` locks
it in and the true score at line 63 is discarded. This is not a missing row — it is
a **wrong row that looks valid**, and it passes the `0 <= n <= 100` sanity check.

**Repro.**

```
$ python -c "

spec=importlib.util.spec_from_file_location('pvp','scripts/price_vs_position.py')

metals=[v for k,v in pos.items() if k.startswith('Metals')][0]
print('parsed Metals scores :', {k:metals[k] for k in ['SCCO','FCX','HBM','ERO']})
truth={}
for line in open('briefings/rank_thesis4_metals_2026-08-12.md'):
    c=[x.strip() for x in line.strip().strip('|').split('|')]
    if len(c)>=3 and re.fullmatch(r'\d+',c[0]) and re.fullmatch(r'\*\*[A-Z.]+\*\*',c[1]):
        truth[c[1].strip('*')]=c[2]

print('quadrant with the corrupted score, FCX cheap_pct=54 ->', m.quadrant(27,54.0))

quadrant with the TRUE score,      FCX cheap_pct=54 -> positioned, NOT fully priced
```

**Impact.** FCX is the copper thesis's #2 name (84 %) and its cheapness percentile
is 54 — it belongs in **"positioned, NOT fully priced"**, the single quadrant the
playbook (Step 4/5) tells the user to hunt for and the *only* input to
`open_questions.py` §1. Instead it is filed as a reject and sorted into the bottom
half of the table (rows are ordered by the corrupted score). HBM (79→9) and ERO
(74→4) are demoted the same way. Precisely the failure this file's docstring says
was already fixed twice — and it is worse than the earlier versions, because the
value is wrong rather than absent, so nothing downstream can detect it. The same
regex is used in `open_questions.py` §3 (line 245), where FCX/HBM/ERO would be
silently withheld from the ≥70 % list by the same first-match rule if the
short-interest cell happened to hold a number ≥70.

## 2. `python scripts/journal.py close` always crashes — an entry can never be closed

**Severity: CRITICAL**

**What breaks.** `journal.close()` assigns a date string into `df["close_date"]`.
For any journal in which nothing has been closed yet, that column round-trips
through CSV as all-empty → pandas 3.0 types it `float64` → the assignment raises
`TypeError: Invalid value '2026-08-13' for dtype 'float64'`. The exception is
uncaught (`scripts/journal.py` only catches `ValueError`, and only for `add`), the
CLI exits 1 with a raw traceback, and because the crash happens *before*
`save()`, the close is silently lost. Playbook Step 8 is therefore unexecutable
from a clean journal — which is the state `journal/decisions.csv` is in right now.

**Repro** (sandbox journal built entirely through the real CLI):

```
$ cd <sandbox>            # journal/decisions.csv holds 7 entries added via `journal.py add`
$ python scripts/journal.py close --id 0001 --reason "falsifier tripped"; echo "EXIT=$?"
Traceback (most recent call last):
  ...
  File ".../stocklab/journal.py", line 102, in close
    df.loc[m, "close_date"] = str(pd.Timestamp(
    ~~~~~~^^^^^^^^^^^^^^^^^
  ...
TypeError: Invalid value '2026-08-13' for dtype 'float64'
EXIT=1
$ grep -c ",closed," journal/decisions.csv
0                       # the close was silently lost
```

**Impact.** Nothing can ever leave `open`. Every entry past 30 days shows
`CHECK FALSIFIER` forever, `score()["open"]` only grows, and the design's central
promise — "an entry without a falsifier cannot be closed honestly" — inverts into
"no entry can be closed at all". The `close_reason` assignment on the next line
has the identical defect.

## 3. `open_questions.py` §1 reports "that is a complete answer" when its input file is missing — 17 real disagreements → 0

**Severity: HIGH**

**What breaks.** §1 reads `briefings/price_vs_position_{as_of}.md` where `as_of`
comes from the **analysis pack**, while `price_vs_position.py` names its output
after the **price panel's last date** (`iso = str(panel.dates[-1].date())`). When
those differ — a stale pack, an aborted `analyze.py`, a price refresh that lands a
day later — the file is absent and the `if pvp.exists()` branch is skipped. The
`else` prints a *confident* claim of emptiness rather than a warning, and the
console summary prints `disagreements: 0` as though that were a measurement.

**Repro** (same pack, same data; only the price table is moved aside):

```
$ cd <sandbox>
$ python scripts/open_questions.py
disagreements: 17 | orphan physical signals: 3 | unpriced high-rated: 0

$ mv briefings/price_vs_position_2026-08-12.md /tmp/pvp.bak
$ python scripts/open_questions.py
disagreements: 0 | orphan physical signals: 3 | unpriced high-rated: 8
$ sed -n '5,9p' briefings/open_questions_2026-08-12.md
## 1. Where the research and the price disagree

*The only place a variant view can exist. …*

*None this week — every researched name is either priced for perfection or cheap for a reason. That is a complete answer.*
```

**Impact.** This file exists because a prose summary once reported a week as
"nothing to do" while live leads sat unread. The identical false negative is now
produced *mechanically*, in stronger language ("That is a complete answer"), and
the playbook makes it Step 0. 17 leads → the user is told there were none. §2 and
§2b still print, so the document looks healthy.

## 5. The SPY benchmark is not time-aligned — every excess return is off by a day or two

**Severity: HIGH**

**What breaks.** `journal._price_on()` returns "last non-NaN close on or before
`when`" **independently** for the position and for SPY, with no tolerance and no
staleness check. Under a partial refresh the two legs land on different days.
At audit time SPY's last print was **2026-08-10** while **93 % of the universe**
was priced 08-11 or later, so `review()` measured every position to 08-11/08-12
and the benchmark to 08-10.

## 7. `MIN_MEANINGFUL_N` gates only the verdict string, and it counts a different population than the statistic it unlocks

**Severity: HIGH**

**What breaks.** Three separate defects in `journal.score()`:

1. `blk()` returns `hit_rate_vs_spy`, `mean_excess`, `best`, `worst` at **any**
   n. `MIN_MEANINGFUL_N` only swaps the `verdict` string. The module docstring
   claims "the scorecard refuses to report a 'hit rate' as meaningful below
   MIN_MEANINGFUL_N"; the playbook says "will refuse to give you a verdict before
   20 decisions". Both are false — a machine or a human reading
   `held_or_watched.hit_rate_vs_spy` gets `1.0` from **one** observation, with no
   caveat inside that block.
2. `n = reviewed["excess"].notna().sum()` counts **all** actions, but the
   `t_stat_vs_spy` that the gate unlocks is computed only on `held`.
3. `t` is silently forced to `0.0` when `len(e) <= 1`, producing the verdict
   "no evidence of an edge vs SPY yet" from an empty computation.

**Repro** — 19 passes + 1 buy (temp CSV, real panel):

```
=== T3: MIN_MEANINGFUL_N vs the population the gate counts ===
{ "n_decisions": 20,
  "held_or_watched":         { "n": 1,  "hit_rate_vs_spy": 1.0, "mean_excess": 0.2919, ... },
  "passed_scored_inverted":  { "n": 19, "hit_rate_vs_spy": 0.0, ... },
  "t_stat_vs_spy": 0.0,
  "verdict": "no evidence of an edge vs SPY yet" }
```

and at n=1:

```
=== T2 ===
score: {"n_decisions": 1, "held_or_watched": {"n": 1, "hit_rate_vs_spy": 1.0, "mean_excess": 0.0176, ...},
        "verdict": "1 scored decisions — TOO FEW TO MEAN ANYTHING. …"}
```

**Impact.** The scorecard's one safety feature — refusing to flatter a small
sample — does not protect the numbers a reader actually looks at. A 100 % hit rate
from one decision is printed as a headline field, and the "20 decisions" gate can
be satisfied entirely by decisions that contribute nothing to the statistic.

## 8. `exit` decisions are counted by the sample-size gate but scored by neither block

**Severity: HIGH**

**What breaks.** `ACTIONS` contains five values; `score()` partitions only
`{watch, starter, add}` and `{pass}`. `exit` rows fall through both filters yet
are counted in `n_decisions`, which is what `MIN_MEANINGFUL_N` compares against.

**Repro.**

```
=== T13: score() population accounting on a mixed book ===
   held n=3 + passed n=1 = 4 but n_decisions=6

=== T4: 20 'exit' decisions — counted by the gate, scored by nothing ===
{ "n_decisions": 20,
  "held_or_watched":        { "n": 0 },
  "passed_scored_inverted": { "n": 0 },
  "t_stat_vs_spy": 0.0,
  "verdict": "no evidence of an edge vs SPY yet" }
```

**Impact.** A book of 20 exits produces a verdict — "no evidence of an edge vs
SPY yet" — from zero scored observations. Exits are also the decisions most worth
scoring inverted (a good exit is one that went on to lag), and they are discarded
without a word.

## 11. `weekly_briefing.py`'s misalignment guard disables its freshness guard

**Severity: MEDIUM**

**What breaks.** `stale = source == "live" and args.as_of is None and (...)`.
When `load_panel()` returns `"live-misaligned"` the equality fails, so a
misaligned store can be arbitrarily stale and still produce a full briefing. The
two guards are meant to compose; instead the newer one switches the older one off.

**Repro — same inputs, only the `source` string differs.**

   STALE NOTICE WRITTEN (guard fires when source=='live')

**Impact.** The run that is *least* trustworthy is the one exempted from the
staleness check. It also writes `briefings/state.json` with
`"source": "live-misaligned"` — and nothing downstream reads that key, so
`open_questions.py` uses those attention ranks with no idea how they were made.

## Checked and CLEAN

Verified by execution, not by reading:

- **The `str(NaN)=="nan"` falsifier bug is genuinely fixed.** `close_date`
  round-trips as `float64 NaN` (`str(v) == 'nan'`, still truthy), and
  `pd.notna(cd) and str(cd).strip().lower() not in ("","nan","nat")` correctly
  reports the entry as open: `days: 191 | check_falsifier: True`. It is also
  robust to hand-written `'nan'`, `'NaT'`, `'  '`, `'None'`, `'null'` — all five
  keep the entry open and the falsifier check armed. No other truthiness-on-NaN
  bug was found in the four scripts; the remaining `if px and …` / `if bpx and …`
  guards in `review()` are truthiness on *floats* (a 0.00 price would read as
  missing) and are harmless on real data.
- **Passes really are scored inverted, and the arithmetic is right.** XOM excess
  +4.30 % → −0.043; T excess −18.01 % → +0.1801; `hit_rate 0.5`,
  `mean_excess 0.0685`, `best 0.1801`, `worst −0.043` — reproduced by hand.
- **A closed entry's benchmark is read on the close date.** AAPL closed
  2026-04-01: `ret −0.053257`, `bret −0.057764`, `excess +0.004507`, matching an
  independent computation from `AAPL@2026-04-01 = 255.63`, `SPY@2026-04-01 = 655.24`.
  `days = 58`, `check_falsifier = False`. (The *open*-entry path is not aligned —
  finding 5.)
- **The falsifier flag fires as designed** on open entries ≥30 days old, and the
  CLI prints the falsifier text underneath each flagged row.
- **`find_targets.py`'s ordering guard fires for the cases it was built for.**
  Stale pack → exit 3, missing pack → exit 3, no output file written in either
  case. (Content-blindness is finding 12.)
- **`price_vs_position.py`'s accumulation fix is real.** All 8 ranking files inside
  the 100-day window are kept — 8 groups, 120 companies, each labelled with its own
  research date and age. The 63-company regression is gone: PWR, CEG, ARCC and AEP
  are all present in the regenerated table.
- **`load_positioning`'s date-window filter is correct** for well-formed names:
  ISO-string comparison against `cutoff` orders correctly, and the "score cell may
  carry trailing annotation" case works (`| 5 | **BCSF** | **63%** *(LOW-conf.)* |`
  parses as 63).
- **`_latest()` glob ordering is safe** for `analysis_pack_YYYY-MM-DD.json` —
  lexicographic order equals date order for that naming scheme.
- **`PROXY_TO_FIELDS` covers every proxy that exists.** All 20 tickers with GICS
  sector `Thematic Proxies` in `broad_sectors.csv` appear in the pack's movers list
  and all 20 are keys in the dict; the `unmapped` reporting path has nothing to
  report. (The dead `Solar Energy` target is finding 17.)
- **`weekly_briefing.py`'s delta section gates correctly.** With `prev.source =
  "live"` and `source = "live-misaligned"` it suppressed the section and printed
  the reason. Field membership was identical across the 08-11/08-12 runs (130
  fields, 0 membership changes, 0 deltas ≥ 0.15), so the `prev_members == n_members`
  condition discarded nothing here — though it is a silent skip by construction and
  would drop a real mover the week a field gains or loses one company.
- **`weekly_briefing.py`'s alignment guard itself works**: 4.5 % aligned →
  `source = "live-misaligned"` + a `PARTIAL DATA` banner at the top of the
  briefing, with the correct share and date.
- **`journal.save()` is atomic** (`.tmp` + `replace`), and `journal/decisions.csv`
  is untouched by this audit — it still contains only its header row.
